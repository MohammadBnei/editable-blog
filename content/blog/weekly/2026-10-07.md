## What shipped

**agent-fleet**

- [#248](https://github.com/MohammadBnei/agent-fleet/pull/248) closes three gaps found by comparing against k-k1's agent-fleet. Answers to a blocked question now carry the question itself plus a fixed "do not re-ask" line, because a resumed session can lose the question and Claude was asking it again. Blocking sidecar waits no longer take `timeoutMs`; all share a fixed 45s wait, because `wait_for_agent` defaulted to 120s, past the 60s MCP ceiling. See ADR 0060.
- [#249](https://github.com/MohammadBnei/agent-fleet/pull/249) drops the worker CPU request from 1000m to 100m and adds an image pre-pull DaemonSet. `KubeCPUOvercommit` fired with a single session running: 9.05 of 9.6 cores were already requested at idle.
- [#247](https://github.com/MohammadBnei/agent-fleet/pull/247) brings README and VISION up to date with ADR-0048. They still described Discord ingress, a task queue and shared-PVC worktrees as if they were coming.
- [#250](https://github.com/MohammadBnei/agent-fleet/pull/250) upgrades every dependency, including Go, client-go, mcp-go, TypeScript, mermaid and release-it. It has to be merged by rebase, not squash. It also fixed the local/kind manifests, where core crash-looped, so the "chore" label undersells it.

## What was decided

- **ADR 0060 (agent-fleet):** the cross-session channel stays open on purpose. The peer set is the whole shared OAuth account, including laptop sessions, the channel bypasses transcript, lease auth and the dashboard, and there is no loop cap. All three are recorded as accepted risk.
- **ADR-0051 (infra-bootstrap):** the Hermes dashboard needs native OIDC and forwardAuth together, because `/api/status` is unauthenticated and Hermes has no roles.
- **ADR-0052 (infra-bootstrap):** the forwarded JWT from the proxy provider is HS256, signed with the client secret, not RS256, so Wird's verification changed instead.

## What it cost

The headline PR reversed itself. #248 started by disallowing `SendMessage` and `ListAgents` and setting inbound cross-session messages to refuse. A harness run then showed both tools were already live in production, so the last commits flipped it: allowed, inbound set to accept, risks written into the ADR and ADRs 0041 and 0058 amended. I have not re-run the unprompted-use or accept-inbound behaviour live; only a config test pins it. #249 partly walks back an earlier CPU bump, because the contention came from all the PVs sitting on one node, not from the request size. On the infra side, #265 took six commits, and review rounds kept finding real bugs: systemd `Environment=` quoting dropped `offline_access`, the idempotency comparisons were never true, and a rescue path could park the service dead. The firewall reasoning was wrong twice: the pod-CIDR allow-list was removed, then the claim that pods were excluded was corrected, because Cilium masquerades and every pod is allowed. #268 reversed its own statement about whether a proxy provider's client credentials can be declared, and its grant list was corrected twice (`corpus_meta` is a real table, `leaves` is not). #271 first said the keystore was unreachable from one project and a later commit says it is reachable. The pattern is the same each time: the claim got written before it was checked, and the check came a commit later.
