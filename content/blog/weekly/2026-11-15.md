Window: 2026-11-08 to 2026-11-15. The [previous rundown](/blog/weekly/2026-11-12) already covered up to 11-12, so this one focuses on what came after. Most of the work was in `infra-bootstrap` again. `agent-fleet` started tracing its own sessions, and `editable-blog` was quiet: nothing merged, and [#29](https://github.com/MohammadBnei/editable-blog/pull/29) is still waiting for my review.

## What shipped

**infra-bootstrap**

- **Voice, self-hosted.** One LiveKit SFU now serves both the shared world and a new meetings app ([#417](https://github.com/MohammadBnei/infra-bootstrap/pull/417), [#425](https://github.com/MohammadBnei/infra-bootstrap/pull/425)). Signalling is exposed on `/rtc` only, so the admin API stays internal. TURN over TLS on 443 covers networks that block UDP.
- **One login for every app** ([#431](https://github.com/MohammadBnei/infra-bootstrap/pull/431)): one login flow, one sign-up flow and one recovery flow. Bindings alone decide who gets in, and the screens now carry my own mark instead of authentik's ([#440](https://github.com/MohammadBnei/infra-bootstrap/pull/440)).
- **Prometheus off Longhorn.** The TSDB had been corrupted three times since 10-11, every time through a replica on the same node. It now lives on local disk on one worker ([#415](https://github.com/MohammadBnei/infra-bootstrap/pull/415)), because metrics don't need three network copies. History was reset, and Prometheus now waits whenever that node is down. Longhorn now has metrics and alerts ([#416](https://github.com/MohammadBnei/infra-bootstrap/pull/416)).
- **Traces have somewhere to go.** Tempo is running, with 72h retention and a capped intake, and Alloy now accepts OTLP ([#443](https://github.com/MohammadBnei/infra-bootstrap/pull/443)). Kubernetes events go to Loki ([#418](https://github.com/MohammadBnei/infra-bootstrap/pull/418)).
- **Fences and hygiene.** Ingress fences went up for four namespaces, built from about 80 minutes of observed flows, one commit per namespace so each can be reverted alone ([#436](https://github.com/MohammadBnei/infra-bootstrap/pull/436)). The game's egress is pinned to named hosts ([#412](https://github.com/MohammadBnei/infra-bootstrap/pull/412)). Deleted: orphan databases ([#426](https://github.com/MohammadBnei/infra-bootstrap/pull/426)), unused apiserver histograms ([#427](https://github.com/MohammadBnei/infra-bootstrap/pull/427)), a legacy inventory nothing referenced ([#432](https://github.com/MohammadBnei/infra-bootstrap/pull/432)), and 29 GB of dead runner files once the build runner's disk hit 100% ([#420](https://github.com/MohammadBnei/infra-bootstrap/pull/420), [#421](https://github.com/MohammadBnei/infra-bootstrap/pull/421)).

**agent-fleet**

- **Spans by session.** Core tags its spans with the session id ([#368](https://github.com/MohammadBnei/agent-fleet/pull/368)). Workers now export one span per turn and one per tool call, through the sidecar to core ([#370](https://github.com/MohammadBnei/agent-fleet/pull/370)). The spans carry no prompt or tool content, and they are dropped rather than queued when core is down.
- **Security, partly** ([#365](https://github.com/MohammadBnei/agent-fleet/pull/365)). Alert text is fenced as untrusted. Fork PRs no longer reach the self-hosted build. The auth-disabled break-glass is refused in-cluster unless it is bound to loopback.

## What was decided

- **ADR-0073, one SFU for two apps.** It avoids a second public exposure. The cost is that the separate key buys separate rotation, not isolation, and TURN-TLS skips the WAF, so the TURN credential is its only gate.
- **ADR-0074, one shared login.** It trades per-app front doors for one flow. Anyone with a verified email can now reach the world, and ArgoCD's login page shows a "Sign up" link that grants nothing there.
- **agent-fleet ADR-0083, remote MCP servers** (Proposed). The design is written down, and I rejected building it now because no user needs it yet. Its own caveat: a tool allowlist bounds what an agent can *do*, not what it *reads*.
- **agent-fleet ADR-0070 §6, rebuilt.** A parked permission now resumes through a one-time grant, not an exact replay of the same call. That means one mechanism instead of two, at the cost of a warm pod and a human answer per park. Six questions are still open for me.

## What it cost

Voice took four merges to work. The first LiveKit app pointed at a values file that was never added, and its node IP was still a placeholder ([#422](https://github.com/MohammadBnei/infra-bootstrap/pull/422)). Then Kubernetes' service links injected `LIVEKIT_PORT=tcp://…`, which livekit-server read as its own port flag, and it crash-looped ([#423](https://github.com/MohammadBnei/infra-bootstrap/pull/423)). Then TURN on 443 hit `bind: permission denied` as a non-root pod, which took voice and meetings down until an unprivileged-port sysctl landed six minutes later ([#437](https://github.com/MohammadBnei/infra-bootstrap/pull/437)). #425 had listed that bind as unverified, and it still shipped. The shared login had its own after-merge repair: its blueprint had been in `error` since its first apply, so the branded mails never took effect ([#441](https://github.com/MohammadBnei/infra-bootstrap/pull/441)). The checks did their job: each failure was loud and was fixed within the hour. The pattern behind them is the real cost: #412, #431 and #443 all merged while their bodies still said "do not merge" or "draft for the owner", and no comment records the check they were waiting on.
