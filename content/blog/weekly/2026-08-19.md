Covers 2026-08-12 through 2026-08-19, across `agent-fleet`, `infra-bootstrap`, and `editable-blog` — this is the first post in `/blog/weekly`, using the skill this repo grew last week for exactly that purpose (`editable-blog#11`).

## What shipped

**agent-fleet** carried the week, and the throughline is authentication. The console now federates login to authentik via OIDC (`#216`), `CoreService` authenticates callers with the session's own rotating lease instead of a shared credential (`#215`), and e2e previews sit behind authentik too (`#217`). `basic-admin-auth` — the shared password that used to gate the console — is gone (`#220`). That rollout wasn't clean: a `TrimSuffix`'d OIDC issuer crash-looped the console (`#219`), a shadowed variable broke a build only at release (`#218`), and the sidecar had to stop binding its agent-facing listeners to the pod IP (`#213`). Alongside that: a dashboard UI pass (decisions modal, diff modal, batch actions, markdown tables, `#208`/`#222`/`#224`), a new any-repo cron-or-once scheduler (`#194`), CI now builds all six images and pushes to an in-cluster Zot registry instead of Docker Hub (`#190`-`#193`), and the knowledge journal was cut back to only what a session deliberately writes — pod and session lifecycle events stopped being journaled because nothing ever read them (`#199`/`#201`-`#205`).

**infra-bootstrap** did the groundwork underneath it. Authentik itself got deployed here (`#173`), then ArgoCD and Grafana logins were federated to it (`#175`, `#182`, `#184`-`#186`) — the identity work agent-fleet's console builds on. Also landed: etcd encryption, audit logging, and Cilium encryption as security-hardening phase 6 (`#166`), a per-route origin lock closing a Cloudflare bypass (`#162`), and two build-runner reliability fixes — a `KillMode=process` that was orphaning every listener a restart left behind (`#180`), and a retry check that reported "ok" after 12 failed attempts (`#181`).

**editable-blog** kept to housekeeping: CI now builds and pushes to the in-cluster registry (`#3`-`#6`), `/blog` got sort and search controls (`#9`), mermaid diagrams retry a dropped chunk load instead of showing raw source forever (`#10`), and the two-part retro on rebuilding the cluster went up — published out of order and then corrected (`#7` shipped the `agent-fleet` post as "part 3", `#8` realized the Proxmox rebuild had to come first and renumbered both).

## What was decided

- **ADR-0054** (agent-fleet): build compute stays inside the worker pod, not offloaded to a separate LXC. The blocker wasn't preference — an OOM kills every process in the pod's cgroup regardless of limit size, and there's no credential or channel for a pod to reach an LXC at all.
- **ADR-0055** (agent-fleet): the journal holds only what a session chose to write down. Pod/session lifecycle events already existed in `sessions.pod_phase` and Loki; journaling them a second time had no reader.
- **ADR-0056/0057** (agent-fleet, `#221`): console auth is OIDC inside `core` itself, not a forwardAuth edge middleware — a worker pod can reach `CoreService` directly over the cluster network without ever touching the ingress, so an edge-only gate would have looked solved while leaving that path open. `CoreService` now trusts a session's own lease id rather than minting a new one.
- **ADR-0039** (infra-bootstrap): authentik is the identity provider, Postgres-backed (the original Redis plan turned out unnecessary), four access tiers, plus a LAN break-glass route for when it's down.
- **ADR-0041** (infra-bootstrap): `fleet.bnei.dev` gets native OIDC, same reasoning as ADR-0056. Its Decision 3 flipped mid-week — `basic-admin-auth` was going to stay as a break-glass layer over OIDC, then got dropped entirely (`#191`), so an authentik outage now locks the console out completely, no local-admin fallback.

## What stalled

- **agent-fleet#209 / infra-bootstrap#183**: the forwardAuth tier for `fleet.bnei.dev` and the e2e previews, filed and not built — ADR-0041 replaced the plan with native OIDC instead, so this issue may now be stale rather than pending.
- **agent-fleet#200**: a worker pod can call `DashboardService`, mutating RPCs included, guarded only by a CSRF header. Filed 08-18, still open.
- **infra-bootstrap#153**: ADR-0037 (worker CPU capacity vs agent-fleet bursts) is still a draft, untouched since 08-18.
- `#210`'s own body undercuts its "security hardening — done" title: `fleet.bnei.dev` — the host with agents holding repo-write and cluster RBAC behind it — was still grey at Cloudflare, no WAF, origin IP public, one shared basic-auth password, as of that PR. Some of that gap closed later in the week (`#220` dropped the shared password), but the WAF/origin-IP gap wasn't part of this week's work.
- `#223` self-flags the same shape: removing `cat` from the worker's allowlist is called "accident-reduction, not a boundary" — `head`/`tail`/`grep`/`jq` still read the same environment-leaking path. The real fix, not holding long-lived tokens in the worker at all, is deferred to a future ADR.
- editable-blog: the theme toggle still doesn't re-render an already-open mermaid diagram when you switch light/dark. Reported 08-17, deliberately left alone.
- A same-day save worth naming rather than filing as a stall: agent-fleet's build-runner started failing CI on 08-19 from two runner processes racing on one job's temp directory. It was root-caused and handed to infra-bootstrap by `prompt_agent` rather than fixed directly — infra-bootstrap's `#180` (dropping `KillMode=process`) landed the same morning and matches the fix.

## What it cost

The authentik rollout did not land cleanly, and the failures are worth more than the feature. A `TrimSuffix` on the OIDC issuer crash-looped the console. A shadowed variable built fine everywhere except at release. The sidecar was binding agent-facing listeners to the pod IP, which only mattered once something else on the network could reach them. Each of those shipped, broke, and got fixed inside the same week — the cost of doing identity work on a live console rather than behind a flag.

Two of the fixes underneath were the same bug in different clothes: a `KillMode=process` that orphaned every listener a restart left behind, and a retry check that reported "ok" after twelve failed attempts. Both are things that claim success while doing nothing, which is the failure mode this fleet keeps rediscovering.

And ADR-0041 flipped mid-week: `basic-admin-auth` was going to stay as a break-glass layer, then was dropped outright. That is the honest trade — one fewer shared password, and an authentik outage now locks the console out completely, with no local fallback. It was written down as a decision rather than discovered later as a surprise, which is the only reason it counts as a choice at all.
